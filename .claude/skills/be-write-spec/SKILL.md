# Write a spec

To hand off writing and running specs, use the `spec-writer` agent; it follows this file.

Jest config is in `package.json`: `rootDir: src`, `testRegex: .*\.spec\.ts$`, module aliases `src/*` and `config/*`. Specs live next to the code.

```bash
npx jest src/patient-registration/patient-notes.controller.spec.ts
npx jest -t "pushes the note"
npx jest --findRelatedTests src/audit/audit.diff.ts
npx jest src/audit                       # a folder
```

No database, Redis or network is available in tests. Never connect to a real environment.

Measured on `development` (Oct 2026): the first Jest run takes ~70s (ts-jest compile); `src/audit` + `sqltomongoquery` = 140 tests passing; specs importing `config/config` fail with `Cannot read properties of undefined (reading 'PORT')` when there is no `.env`, and pass with `NETWORK=DEV`. Jest prints "a worker process has failed to exit gracefully" (open handles in some services); it is noise, not a failure. `node --test test/notification-queue-delivery.cjs` has **5 failing tests already on development** (IP vitals object/array events, read/bulk-read closing copies, legacy task copies); compare against that baseline rather than treating them as yours.

## Pattern 1: controller/service with a fake DB (preferred)

Copied from `src/patient-registration/patient-notes.controller.spec.ts`:

```ts
import { DBService, TABLE_NAMES } from 'config/config';
import { PatientRegistrationController } from './patient-registration.controller';

describe('patient notes endpoints', () => {
  const tenantCheck = { tenant_schema: 'TENANT_DB' };
  let db: { findByUniqueValue: jest.Mock; addItemQuery: jest.Mock };
  let controller: any;

  beforeEach(() => {
    db = { findByUniqueValue: jest.fn(), addItemQuery: jest.fn() };
    controller = new PatientRegistrationController(null, null, null, null, null, null, null, null, null); // one null per constructor arg
    controller[DBService] = db;            // DBService === 'mongoDBService'
  });

  it('reads from the tenant schema', async () => {
    db.findByUniqueValue.mockResolvedValue({ patient_notes: { messages: [] } });
    const res = await controller.getPatientNotes({ tenantCheck }, 'tenant-1', 'UHID1');
    expect(db.findByUniqueValue).toHaveBeenCalledWith(TABLE_NAMES.PATIENT_REGISTRATION, 'registration_id', 'UHID1', 'TENANT_DB');
    expect(res.statusCode).toBe(200);
  });
});
```

- Always assert the **tenant schema argument**; that is the most common real bug.
- Assert on returned `statusCode` (handlers return 4xx in the body rather than throwing).
- For services that call `this.mongoDBService.x`, pass the fake as the constructor argument.
- Importing a controller pulls in `config/config`, which runs `dotenv.config()` and indexes `CONFIG_PARA[process.env.NETWORK]` at load. Locally your `.env` supplies `NETWORK`; without one (CI) run `NETWORK=DEV npx jest ...` or `jest.mock('config/config', ...)`. Setting `process.env.NETWORK` inside the spec only works with `require` after the assignment, because `import`s are hoisted.

## Pattern 2: pure functions

Prefer extracting logic into `*.util.ts` and testing it directly: `audit.diff.spec.ts`, `discharge-edits.util.spec.ts`, `pincode-lookup.util.spec.ts`, `patient-notes.util.spec.ts`, `facilityCountry.spec.ts`, `sqltomongoquery.spec.ts` (SQL -> pipeline assertions; uses `mingo` to run pipelines in memory).

## Pattern 3: gateways and env-dependent modules

`src/conversation-ai/conversation-ai.gateway.spec.ts`: set `process.env.*` **before** `require` (env is read at module load), `jest.mock('config/config', ...)`, mock `ws`, stub `setInterval` so timers don't keep Jest alive, and end the file with `export {}` so top-level names don't clash with other gateway specs.

## Pattern 4: notification queue delivery

`test/notification-queue-delivery.cjs` uses `node:test` with `vm` + `ts.transpileModule` to load `src/notification/*.ts` with stubbed requires. Run with `node --test test/notification-queue-delivery.cjs`. Extend it when changing SQS/Kafka/DB queue behaviour.

## Avoid

- `Test.createTestingModule` with real `MongoDBService` (e.g. `appointment.controller.spec.ts`) tries to connect to Mongo; prefer Pattern 1.
- The 19-line "should be defined" stubs generated by Nest fail without full DI; don't add more of them.
- Snapshotting whole clinical payloads; assert the fields that matter.
